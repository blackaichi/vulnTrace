## RWF-162 — A getter on `URL.prototype` redirects a package resolved through `exports`

**Status:** Open (backlog `BL-122`)
**Failure class:** false `NOT_AFFECTED`
**Defect class:** B (the analyzer takes Node's loader to turn a resolved
URL into a path with Node's own `URL` accessors; a module may have
replaced them)
**Proof family affected:** B (BL-092's setup)
**Severity:** P0 / a live false `NOT_AFFECTED`, pre-existing
**Fix lane:** C, with lane A's builtin-store facts (a closure-wide fact,
as RWF-156), or the trust boundary, by the project owner's decision

**Discovered:** by task BL-113's independent audit (round 2), against
real Node v22.11.0, on the branch (no analyzer change, so the base gives
the same answer). Real Node calls the target and the analyzer answers
`NOT_AFFECTED`, family B (`tests/oracle/bl113-trust-boundary.cases.ts`,
`outside.url-prototype-pathname`, an open-soundness-defect record; its
control `control.url-exports-no-change` answers `NOT_AFFECTED` and real
Node does not call the target):

```js
// wrap/index.js, before `require("vuln-lib/index.js")`; the decoy
// wrap/node_modules/vuln-lib declares "exports": { ".": "./index.js", "./index.js": "./index.js" }
const d = Object.getOwnPropertyDescriptor(URL.prototype, "pathname");
Object.defineProperty(URL.prototype, "pathname", {
  configurable: true, enumerable: true, set: d.set,
  get() { return d.get.call(this).replace("/wrap/node_modules/vuln-lib/", "/vuln-lib/"); },
});
```

**The mechanism.** For a package with an `exports` field, Node's
CommonJS loader resolves the subpath to a file URL and converts it with
`fileURLToPath`, which reads the URL's `pathname` through
`URL.prototype`'s accessor. A getter defined there returns another path,
and the loader loads the affected top-level instance instead of `wrap`'s
decoy. The program uses no loader state.

**Why it is not the boundary's case.** The trust boundary
(SOUNDNESS-CONTRACT § 1, task BL-113) covers the ECMAScript intrinsic
prototypes only, the narrower reading of the owner's "Node's builtin
prototypes" (ADR 0010, "Decision record — BL-111"). `URL.prototype` is
Node's own builtin prototype, so this route is an open defect. Under the
decision's broader reading it would be the boundary's case: backlog
`BL-122` brings the reading, and this route, to the owner.

**Not measured:** other releases than v22.11.0; Node's other builtin
prototypes the loaders read (`Buffer.prototype`, `EventEmitter.prototype`
and the ES module loader's own objects).

## RWF-162 — BL-122: an unspelled form; Node's other prototypes measured

**Status update (task BL-122, 2026-11-02): still open, now before the
project owner** (ADR 0010, "Proposed decision — BL-122"; backlog
`BL-126` implements the decision).

- **`URL.prototype` reached without its name is live too.** A `pathname`
  getter defined on `Object.getPrototypeOf(new URL("file:///x"))` makes
  real Node call the target and the analyzer answer `NOT_AFFECTED`,
  family B, on the base (`tests/oracle/bl122-trust-boundary-reach.cases.ts`,
  `o2.url-prototype-unspelled`, an open-soundness-defect record). A rule
  over spelled prototypes (`RS.patch`) leaves it live.
- **"Not measured" answered for the CommonJS loader.** On 13 releases
  from v20.19.0 to v26.12.1, the loader touches `URL.prototype`'s
  `pathname`, `href`, `protocol`, `hostname` and `toString`, and
  `Buffer.isEncoding` (Buffer's own, which chooses no load); nothing on
  `Buffer.prototype` or `EventEmitter.prototype`
  (`scripts/bl122-trust-boundary-reach/results.md`). The ES module
  loader touches more of `URL.prototype` (`hash` and `search`, read and
  set, on `require()` of an ES module), `Buffer`'s and
  `EventEmitter.prototype`'s members (on `import()`): the inventory is in
  `scripts/bl122-trust-boundary-reach/reach-releases.md`; none of these
  was tried end to end.
