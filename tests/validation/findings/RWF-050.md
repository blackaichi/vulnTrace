## RWF-050 — RWF-026's inherited MAY-execute conditional/logical abrupt-operand gap, given a register row

**Status:** Open — **UNCLASSIFIED**
**Failure class:** possible false `NOT_AFFECTED` (not independently reproduced; awaiting reproduction)
**Defect class:** not classified — unclassified
**Proof family affected:** not classified — unclassified (plausibly C, by analogy with RWF-016/RWF-026's own family, but not confirmed)
**Severity:** not rated — unclassified
**Fix lane:** none assigned. RWF-026's own text calls closing this "a design question this task was explicitly scoped away from"; it is the natural candidate for whichever task takes the conditional-operand axis next.

RWF-026 closed the "definitely-abrupt call in a necessarily-evaluated
expression position" family, but its own "Remaining limitations"
section states explicitly that a **MAY-execute** conditional or logical
operand (`flag && bail()`, `flag ? bail() : v`, `z ||= bail()`) is a
"separate, INHERITED family" that RWF-026 "neither introduces nor
widens" and does not close: on a truthy `flag`, the later export really
is unreached in real Node, exactly as in RWF-026's own MUST-execute
cases, but `mayEndModuleEvaluation`'s MAY relation does not extend to a
conditional operand the way it already does to an `if`/loop body. RWF-026
calls this "a real, tracked gap, not a settled one" and leaves deciding
whether the operand model should become MAY like the statement model to
a future task.

This entry gives that gap a register row, per `AGENTS.md` § E ("no known
path to a false `NOT_AFFECTED`" is a claim the register must be able to
state truthfully) and this task's instructions. It is recorded as
**UNCLASSIFIED** rather than as a confirmed defect: none of the three
audits behind this task independently reproduced it end to end against
real Node, and no defect class, proof family, severity or fix lane can
be honestly assigned without that reproduction. A future task should
reproduce it (or show it does not reach a real verdict) before
classifying it further.

Full account: `tests/validation/FINDINGS.md`, "RWF-026 ...", section
"Remaining limitations (deliberately not fixed here)" (this same file,
above) — this is a correction to the register's own stated gap, not new
report content from `docs/audits/`.

**Status update (task RWF-050-repro, 2026-10-12): reproduced and
classified. Still Open.** This supersedes the UNCLASSIFIED lines above.

- **Failure class:** false `NOT_AFFECTED`, with a complete family C proof.
- **Defect class:** C (multi-valued provenance collapsed to one value):
  the export holds the early write's value on every load where the operand
  fires and the later write's value otherwise, and the analyzer keeps only
  the later write.
- **Proof family affected:** C (measured).
- **Severity:** P0 / critical soundness, the same as RWF-015, RWF-016 and
  RWF-026.
- **Fix lane:** E (ADR 0009 § 1 clause 3, "the existing straight-line and
  abrupt-completion machinery … selects a unique last write that
  definitely runs"). Backlog `BL-063`, ordered before `E-1`.

**The mechanism (read at `570a4b6`).** `mayEndModuleEvaluation`
(`src/code-intelligence/module-model.ts`) answers a MAY question ("can
this top-level statement end module evaluation?"). For statements it
answers it as a MAY: it walks into every statement container, so
`if (FLAG) bail();` is a cutoff. For an expression it consults RWF-026's
MUST relation (`isDefinitelyAbruptCallStatement` →
`necessarilyEvaluatesAbruptly`), which refuses every position that is not
necessarily evaluated. So `FLAG && bail();`, which is the same program as
`if (FLAG) bail();`, is not a cutoff, and a later export write stays
authoritative. RWF-026's refusals were right for the question RWF-026
asked (does this expression NECESSARILY end evaluation?), but that is the
wrong question for a MAY cutoff. The same holds for `isDefinitelyAbruptCallStatement`'s
comments on a `do`/`while` condition and a `for` update ("would need
body-completion reasoning this relation does not have"): a MAY cutoff
needs no body-completion reasoning.

**Reproduction (real Node v22.11.0, H-0 oracle harness).**
`tests/oracle/rwf050-may-execute-operand.cases.ts` and `.test.ts`. A
package `wrap` whose `index.js` requires `./b` first (`b.js` keeps the
exports object and reads `.run` only when called), then writes
`exports.run = dangerousOp` (calls `vuln-lib`'s `parse`), then one
MAY-abrupt top-level operand, then `exports.run = safeOp` (calls `safe`).
The entry catches the throw from `require("wrap")` and calls
`require("wrap/b").later("x")`. With the flag truthy (real Node), Node
calls `parse`. An uncaught module-scope throw removes the module from
`require.cache`, so a module that already holds the exports object is
the only way to observe the partial value. The cycle runs before both
writes, so ADR 0009 § 1 clause 4's observation point (a re-entrant
`require` BETWEEN the writes) is absent: lane E's clause 4 does not close
these cases, and only the abrupt-completion machinery decides.

Every false result is the same observation: `vuln-lib#parse`,
`reachableSubgraphComplete: true`, 0 unknown edges. Each is pinned as an
open-soundness-defect record (`RWF-050`, `D-17`, expected `UNKNOWN`). The
last three rows are RWF-026's other refused positions. The `do`/`while`
and `for` rows, with an empty body, are not even conditional: the
condition and the update are reached on every load.

**Mutation (throwaway, reverted).** A prototype that makes every
module-time definitely-abrupt call outside a function body a MAY cutoff
flips all 13 records to `UNKNOWN` (each fails with "the live result … is

**Status update (task BL-063, 2026-10-12): Fixed.** This supersedes the
"Still Open" lines above.

- **The fix** (`src/code-intelligence/module-model.ts`,
  `mayEndModuleEvaluation`): the cutoff is MAY for expressions as it was
  for statements. Any call or construction `isDefinitelyAbruptCall`
  proves can only throw, reached by the walk at module time and not caught
  within its top-level statement, is a cutoff. The walk is opened into
  expressions for every file with a definitely-abrupt callable
  (`fileHasDefinitelyAbruptCallable`, the same cheap gate RWF-026 uses).
  Two positions the walk reaches are excluded because module evaluation
  never evaluates them (`isNeverEvaluatedAtModuleTime`): an instance
  field's initializer, and a `for` incrementor or `do`/`while` condition
  whose body always leaves by `break` first (`bodyAlwaysBreaks`: a `break`
  among the body block's own statements with no `continue` before it). A
  method's or accessor's computed key is walked; its body is not. RWF-026's
  MUST relation is unchanged and still answers.
- **Reproductions flipped.** All 13 open-soundness-defect records are
  deleted and assert `UNKNOWN` with real Node calling the target
  (`tests/oracle/rwf050-may-execute-operand.*`). Nine more MAY spellings,
  each measured as a further live false `NOT_AFFECTED` on the base, assert
  `UNKNOWN` too: a static field, a static block, an instance field's
  computed key, a method's computed key, an object literal's computed key,
  a heritage expression, a construction (`FLAG && new Bail()`), a `switch`
  case test and a `try` with no `catch`. Six precision controls keep
  `NOT_AFFECTED` (a function body, an arrow body, an instance field, a
  caught call, both `break`-guarded loops).
- **Inverted rows.** 41 tests: 40 unit "keeps authority" rows in the
  RWF-016, RWF-017, RWF-018, RWF-019, RWF-020, RWF-024, RWF-026 and
  RWF-028 suites, and the RWF-026 integration test, now assert the
  withdrawal. The
  prototype's 48 failures included the `break`-guarded loop rows and one
  nested instance-field row; `bodyAlwaysBreaks` and the instance-field
  exclusion keep those (7). Every program whose cutoff moved anywhere in
  `npm test`, the adversarial, binding-grammar, validation and oracle
  suites (61) was run under real Node with `FLAG`, `MODE` and `obj` free:
  50 end module evaluation on some load (bail's exception, or once a
  `TypeError` before `bail`), 2 more under their fixture's environment
  variables, and 9 never do. Those 9 are precision costs, not claims: the
  operand is correlated with its own guard (`if (FLAG) { FLAG || bail(); }`)
  or a constant (`let z = 1; z ||= bail();`, `obj.m?.()` on `{}`,
  `first || bail()`), and the cutoff has no value semantics. Each is
  labelled `precision-cost` in its test. Where an old row's spelling was
  only correlated, the MAY row now reads a second free variable `MODE`.
- **Corrections 1 and 2 applied.** The RWF-026 `REFUSED` doc comment and
  ADV2-086's expected-verdict rationale (`tests/adversarial/v2/expected.json`)
  now say what real Node does. The same false premise sat in
  `fixtures/commonjs-expression-position-throwing-call-export-authority/node_modules/fixture-lib/conditional.js`
  ("all four are proven safe"): with `FIXTURE_LIB_MODE=fast` and
  `FIXTURE_LIB_FLAG` set, its `&&` operand throws (measured); corrected
  there, and the integration test asserts `UNKNOWN`.
- **Correction 3 decided.** ADR 0009 § 8 carries a decision record: E-1's
  precision acceptance names the RWF-013 … RWF-028 controls as they stand
  after BL-063.
- **The exclusions are for the MAY check only.** The `return`/`throw`
  and RWF-016 … RWF-026 MUST predicates keep their earlier reach, so a
  literal `throw` in a class static block nested inside an instance field
  (`class C { f = class { static { bail(); } }; }`) still withdraws though
  Node never runs it: a pre-existing precision cost, not a regression
  (found by BL-063's independent audit).
- **Independent audit:** CERTIFIED (56 shapes probed against the analyzer
  and real Node). Its pre-existing findings are RWF-094's further shapes
  and RWF-095, below.
- **Not closed by this fix: RWF-094**, found by it. A module-time call
  that MAY throw through a callee no proof reaches (`maybe(FLAG)`,
