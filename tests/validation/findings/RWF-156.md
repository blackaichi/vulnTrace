## RWF-156 — A replaced builtin receives the lookup state from Node's own loader

**Status:** Open (decision, backlog `BL-111`; implementation `BL-113`)
**Failure class:** false `NOT_AFFECTED`
**Defect class:** B (the analyzer takes Node's loader to touch its lookup
arrays through Node's own builtins; a module may have replaced what those
writes run)
**Proof family affected:** B (BL-092's setup)
**Severity:** P1 / a live false `NOT_AFFECTED`, pre-existing
**Fix lane:** C, with lane A's builtin-store facts (it needs a closure-wide
fact, not a per-use rule)

**Discovered:** by task BL-096's independent audit (round 2), against real
Node v22.11.0, on the base `904d032` and under every option BL-096
prototyped, `NOT_AFFECTED` (`tests/oracle/bl096-module-paths-read-only.cases.ts`,
`audit2.index-setters-loader-unshift`, `audit2.proxy-parent-set-trap`,
`audit2.paths-setter-in-entry`):

```js
// wrap/index.js, before `require("vuln-lib/index.js")` -- no use of module.paths
for (let i = 0; i < 40; i++)
  Object.defineProperty(Object.prototype, String(i), {
    configurable: true,
    set(v) { drop(this); Object.defineProperty(this, String(i), { value: v, writable: true, enumerable: true, configurable: true }); },
  });
```

There are three more forms: a Proxy with a `set` trap as
`Array.prototype`'s [[Prototype]]; a `paths` setter on `Object.prototype`
that the application's entry installs before it loads `wrap`; and, found by
round 3, a plain data store `Array.prototype.constructor = C`, where `C`'s
`Symbol.species` returns a Proxy (`audit3.species-constructor-store`).
`ArrayPrototypeSlice` in `_resolveLookupPaths` honours the species, so
the loader builds its combined lookup array as that Proxy and `unshift`s
into it.

**The mechanism.** Node's loader builds and writes lookup arrays in
JavaScript. `Module._resolveLookupPaths` `unshift`s onto a combined array
(loader:936 on v22.11.0), and `Module.prototype.load` assigns `this.paths
= …` (loader:1304). An array write onto an index the array does not own
yet, and a property assignment of a name the object does not own, run an
inherited setter or a Proxy's `set` trap. That code receives the array
Node resolves from, so the next load reads the module it chose. The
program never uses the lookup list, so no rule over the list's uses
(RWF-136's options (b0), (b1), (b2)) can see it. Only a closure-wide fact
can: "a loaded file may define an accessor on a builtin prototype, change
its [[Prototype]], or store its `constructor` (and so its species)". The
species form shows that accessors and [[Prototype]] changes alone are too
narrow. That is option (a)'s precondition. It is complete
only as the escape row's whole relation, which is not certified (ADR 0008,
BL-094's proposed decision). The probes BL-096 committed check only
whether user code receives `module.paths` itself, so by construction they
cannot see a copy.

**Wider than lookup arrays (round 4).** Node's own plain stores reach more
than the lookup arrays. `makeRequireFunction` assigns `require.extensions =
Module._extensions` and `require.cache = Module._cache`, and the `Module`
constructor assigns `this.id`, `this.path`, `this.filename`, `this.loaded`
and `this.children`. Each runs an inherited setter on `Object.prototype`.
An `extensions` setter replaces the `.js` handler, and a `cache` setter
reaches `wrap`'s own cache entry and shifts its `paths`. Both are live with
no loader API spelled (`audit4.extensions-setter-registry`,
`audit4.cache-setter-registry`). So the fact that closes the class covers
an accessor on `Object.prototype` under any name, not only index or
`paths` names.

**Not decided here.** Whether such a store widens the module-load closure
is a design question across lanes A and C: backlog `BL-111`.

**Inventory and options (task BL-111, 2026-10-26).** Measured from Node
v22.11.0's own loader source and against real Node
(`scripts/bl111-loader-writes-options/inventory.md`). The class is the
loader's own JavaScript acting, by inheritance, on what a loaded file
changed:

- **writes** onto every `Module` it creates and every `require` function;
- **writes** into the arrays it builds;
- arrays built through the receiver's **species**;
- **reads** of data properties.

Every write and species route is live (this record's six oracle cases).
The reads add one more route: in real Node, a plain *primitive* store,
`Object.prototype.source = <module text>`, replaces an ES module's source.
With the analyzer it is `UNKNOWN`
(`tests/oracle/bl111-loader-inherited-reads.*`), because on v22.11.0 an ES
module loads after a store only through `import()`, which already widens
the closure. Its status on releases with `require()` of an ES module is not
measured (backlog `BL-114`).

The stores that reach the loader are:
- a define call (data or accessor);
- a [[Prototype]] change;
- a store of `constructor`;
- a store under a computed key.

The record's earlier statement that "an accessor on `Object.prototype` under
any name" closes the class is too narrow: species is reached by a plain
data store.

The class is also wider in how the store is made. BL-111's independent
audit found, by reading the prototype, that a rule which recognises storing
builtins by name misses one reached indirectly (through an alias or an
indirect call). A measurement confirmed it for three such forms: each is a
live false `NOT_AFFECTED` on the base and under the prototype. BL-111 proposes a closure-wide rule over these stores, or a
stated trust boundary (ADR 0010, "Proposed decision — BL-111"). Either way
the decision is the project owner's. The sound rule costs 2 of the 4
real-world validation `NOT_AFFECTED` proofs (`RWB-07`, `RWB-11b`). The
status stays Open.

**Other Node releases (task BL-114, 2026-10-27).** BL-111's inventory,
repeated on Node v20.20.2, v22.23.4, v24.22.1 and v26.12.1 and bounded by
release (`scripts/bl114-loader-inventory-releases/releases.md`), adds one
route of this record's class, live only on v20:

- **`trySelf`** (v20's CommonJS loader) destructures `{ data, path }` from
  `readPackageScope`, which is `false` for a module with no package.json
  between it and its `node_modules`. Getters for `data` and `path` on
  `Object.prototype` (a define call) make a bare `require` in such a module
  a self-reference resolved in any directory. Live on v20.19.0 and v20.20.2,
  `NOT_AFFECTED` with the analyzer (`tests/oracle/bl114-require-esm-inherited-source.*`,
  `try-self.scope-getters`, an open-soundness-defect record). A plain data
  store of the two names makes unrelated loads throw.
- **`conditions`**: on v22.23.4, v24 and v26, `require.resolve(x, { paths })`
  reads its options' `conditions` by inheritance, so
  `Object.prototype.conditions = new Set([...])` selects another `exports`
  target. The analyzer already answers `UNKNOWN` for a load through
  `require.resolve` with options, so it is not live with the analyzer.

The `source` read BL-111 found `UNKNOWN` is a live false `NOT_AFFECTED` on
releases where `require()` loads an ES module: RWF-158. The status stays
Open.

**Status update (task BL-113, 2026-11-01): documented limitation.** The
project owner accepted option (C), the trust boundary, on 2026-10-27
(ADR 0010, "Decision record — BL-111"). SOUNDNESS-CONTRACT § 1 now states
it ("The trust boundary: the runtime's built-in prototypes"): every
`NOT_AFFECTED` assumes the program makes no change to the ECMAScript
intrinsic prototype objects, and the scope disclosure carries it
(`BUILTIN_PROTOTYPE_TRUST_BOUNDARY`, one entry of
`SUPPORTED_MODEL_EXCLUSIONS`). Every reproduced form changes a built-in prototype: an accessor or index setter on `Object.prototype`, a Proxy as `Array.prototype`'s [[Prototype]], `Array.prototype.constructor` (its species), and v20's `trySelf` getters. This record is the boundary's
documented case: no analyzer rule changed, and the analyzer's answer is
the same as before. It supersedes the **Status** line above. Its
reproductions are kept as trust-boundary cases
(`src/testing/trust-boundary-case.ts`), no longer open-soundness-defect
records: real Node's ground truth is still asserted, the analyzer's
exact result is still compared, and the verdict a sound analyzer would
give without the boundary (`UNKNOWN`) is stated beside it; no verdict is
pinned as expected. The cases: `tests/oracle/bl096-module-paths-read-only.cases.ts` (`audit2.index-setters-loader-unshift`, `audit2.proxy-parent-set-trap`, `audit2.paths-setter-in-entry`, `audit3.species-constructor-store`, `audit4.extensions-setter-registry`, `audit4.cache-setter-registry`) and `tests/oracle/bl114-require-esm-inherited-source.cases.ts` (`try-self.scope-getters`).

The class reaches beyond the boundary. Task BL-113 measured a species route that changes no prototype: `Object.defineProperty(Array, Symbol.species, …)`, a builtin constructor's own property, which Node's loader's `ArrayPrototypeSlice` honours (real Node v22.11.0 calls the target; the analyzer answers `NOT_AFFECTED`, family B). Whether the boundary reaches a constructor's own properties is not decided, so that route is an open defect, RWF-161, not this record's case.
