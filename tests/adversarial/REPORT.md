## Failures

### ADV-011 -- main() calls vulnerable via one level of `export { vulnerable } from "adv-vuln-lib"` re-export.

- Category: 11. Re-export through one module
- Expected: **AFFECTED**
- Actual: **UNKNOWN**
- Human rationale for expected verdict: The call genuinely executes at runtime; a single re-export hop does not change what actually runs.
- Suspected analyzer component: call-graph construction's re-export handling
- Relevant source files: `src/code-intelligence/call-graph.ts`, `src/code-intelligence/module-model.ts`
- Explanation: ADR-0007 ("Re-exports are not chased", TASK-018) documents that `export { x } from "./y";` is recorded in the module model but never followed to `./y`'s own definition of `x` when building the call graph. A call reached only through such a re-export is not attributed to the real vulnerable-lib function, so it cannot appear as a graph edge to the true target.

### ADV-012 -- main() calls vulnerable through a two-hop `export { vulnerable } from ...` re-export chain.

- Category: 12. Re-export through multiple modules
- Expected: **AFFECTED**
- Actual: **UNKNOWN**
- Human rationale for expected verdict: The call genuinely executes at runtime regardless of how many re-export hops it passes through.
- Suspected analyzer component: call-graph construction's re-export handling
- Relevant source files: `src/code-intelligence/call-graph.ts`, `src/code-intelligence/module-model.ts`
- Explanation: Same root cause as ADV-011 (ADR-0007's documented re-export gap), exercised across a two-hop re-export chain instead of one.

### ADV-018 -- vulnerable() sits behind `if (false)`, a condition that can never be true.

- Category: 18. Conditional branch that definitely does not execute
- Expected: **NOT_AFFECTED**
- Actual: **AFFECTED**
- Human rationale for expected verdict: A statically-dead branch behind `if (false)` never executes at runtime, regardless of the call lexically present inside it.
- Suspected analyzer component: reachability model has no control-flow/dead-code elimination
- Relevant source files: `src/analysis/reachability.ts`
- Explanation: VulnTrace's reachability (docs/SDD.md § 20) is call-graph reachability: whether any call edge exists from an entrypoint to the target, not whether a surrounding branch condition is statically true. A lexically-present call behind `if (false)` is not distinguished from a live one, because the analyzer does no branch-condition/dead-code evaluation -- an explicit, deliberate MVP scope boundary, not an oversight, but one that means 'reachable' does not mean 'provably executes'.

### ADV-019 -- vulnerable is passed by reference to invoke(fn), which calls fn() internally.

- Category: 19. Function passed as a callback
- Expected: **AFFECTED**
- Actual: **UNKNOWN**
- Human rationale for expected verdict: invoke(vulnerable) genuinely calls the vulnerable function through the higher-order function.
- Suspected analyzer component: call-graph edge construction records no edge at all for an indirectly-invoked parameter
- Relevant source files: `src/code-intelligence/call-graph.ts`
- Explanation: Confirmed by direct inspection: the graph correctly records a resolved `direct` edge from main() to invoke() (a same-file direct call), but records ZERO edges -- not even an "unknown" one -- for invoke()'s own `fn()` call on its parameter. A function value passed as an argument and invoked indirectly is not merely mis-resolved, it is entirely absent from the graph: the vulnerable dependency is never flagged as a blocker, it simply does not exist as far as reachability search is concerned.

### ADV-021 -- `new Lib().vulnerableMethod()` invokes a vulnerable instance method.

- Category: 21. Class method invocation
- Expected: **AFFECTED**
- Actual: **UNKNOWN**
- Human rationale for expected verdict: The vulnerable method genuinely runs when instance.vulnerableMethod() executes in main().
- Suspected analyzer component: call-graph traversal never visits the target file for a method call on a locally-constructed instance
- Relevant source files: `src/code-intelligence/call-graph.ts`
- Explanation: Confirmed by direct inspection: identical to ADV-020 -- the graph contains only main()'s own node. `const instance = new Lib(); instance.vulnerableMethod();` never causes adv-vuln-lib's index.js to be visited at all. kind: "method" is a real, named target kind (SDD § 13) with no corresponding graph support for instance-method calls.
