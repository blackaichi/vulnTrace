- Actual: **UNKNOWN**

### ADV2-021 -- The vulnerable behavior is a static method on the package's exported class, called directly on the class (no instance).

- Actual: **UNKNOWN**
- Human rationale for expected verdict: Lib.staticDangerous() calls the real vulnerable static method directly.

### ADV2-022 -- A project-local class extends the package's Base class without overriding the vulnerable method; an instance of the local subclass calls the inherited method.

- Category: 22. Inheritance
- Expected: **AFFECTED**
- Actual: **UNKNOWN**

### ADV2-024 -- The vulnerable function is called inside a `.then()` callback attached to an unrelated resolved promise.

- Category: 24. Promise callback
- Expected: **AFFECTED**
- Actual: **UNKNOWN**
- Human rationale for expected verdict: The .then(() => dangerousOp()) callback genuinely calls dangerousOp() once the promise settles.

### ADV2-028 -- The vulnerable package exports its function under a computed property key (`module.exports = { [NAME]: impl }`) where NAME is a module-top-level string literal; the consumer calls it by its resulting plain name.

- Category: 28. Computed exports

- Actual: **UNKNOWN**
- Human rationale for expected verdict: NAME is a literal ("dangerousOp") fixed at the package's own module scope, so the export is unambiguously named dangerousOp; lib.dangerousOp() is a fully static, unambiguous call to it.

### ADV2-041 -- The vulnerable class IS instantiated, but only its safe method is ever called; the vulnerable method is never invoked on that instance. Traps any heuristic that treats instantiation as proof of full method reachability.
