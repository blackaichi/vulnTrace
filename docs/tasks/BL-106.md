Measured by BL-105's audit: an ES module that hands an imported value on (`[use].forEach(…)`, `register(plugin)`, `b.use(b)`) loses every ES export's attribution when the import may reach back -- a cycle, or a dependency whose load closure is tainted (one `require(process.env.X)`) -- four probes `AFFECTED` → `UNKNOWN`. A named import is a member of the load's result, not the object; a real ES module's exports cannot be written at all. Narrow only where real Node cannot reach the export objects, measured on TypeScript sources; a precision task, no soundness change
