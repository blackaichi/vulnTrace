## Backlog note

Moved verbatim from this task's row in [`BACKLOG.md`](BACKLOG.md)
by task `BL-119` (2026-11-01); the row links here.

Precision, not a defect. An explicit `super(...)` is a `CallExpression` whose callee (`super`) no authority attributes, so it gets an unknown edge today (sound; measured by A-1: `class Sub extends Base { constructor() { super(); } }`, `new Sub()` is `UNKNOWN` although `Base`'s constructor is attributable). A-1's `implicit_super` account already resolves the `extends` expression through the `new` callee's authorities (`classifyConstructee`, `call-graph.ts`); the explicit call could share it. Every reachable derived class with its own constructor currently blocks family C for its region.
