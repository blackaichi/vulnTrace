# Backlog

The single source of truth for task **order** and **status**. Created by
task [`task-0-workflow-bootstrap`](task-0-workflow-bootstrap.md) on
2026-09-27.

What this file does not own:

- **Specifications.** A remediation task's specification is its row in
  [`docs/REMEDIATION-PLAN.md`](../REMEDIATION-PLAN.md) (§ 5a, § 7 and the
  "A-0 additions to lane-A acceptance") and the § 8 table of the ADR it
  names. Every other task's specification is its task file, written when
  the task starts. Nothing is copied here.
- **Findings.** A defect is recorded in
  [`tests/validation/FINDINGS.md`](../../tests/validation/FINDINGS.md); a
  debt in [`docs/OPEN-DEBTS.md`](../OPEN-DEBTS.md). A row here records the
  work that closes them.
- **Measured state.** [`docs/SCORECARD.md`](../SCORECARD.md).

How it is kept (the full rules are in [`README.md`](README.md) and
[`docs/WORKFLOW.md`](../WORKFLOW.md)):

- One task is `IN_PROGRESS` at a time.
- A task's first commit sets its row to `IN_PROGRESS` and the previous
  task's row to `MERGED`; its last commit sets its row to
  `READY_FOR_REVIEW`. `main` changes only through pull requests, so a
  merge is recorded by the next task.
- A finished task stays here as `MERGED` or `CANCELLED`. Rows are never
  deleted.
- Work discovered during a task gets a new row whose source reads
  "discovered in" and the task's ID; a discovered defect is also
  registered in `FINDINGS.md`.
- Row order in § 1 is the order of work. Priority explains the order; it
  does not override a dependency.

## Legend

| Column     | Values                                                                                                                                                                                                                                                                                                                                          |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Status     | `TODO` · `IN_PROGRESS` · `BLOCKED` · `READY_FOR_REVIEW` · `MERGED` · `CANCELLED`                                                                                                                                                                                                                                                                |
| Priority   | `P0` critical soundness or blocking (a live false `NOT_AFFECTED` or silently dropped finding) · `P1` a defect or instrument the soundness work needs soon · `P2` soundness instruments and hardening · `P3` evidence and trust · `P4` explainability and precision · `P5` capability · `P6` hygiene · `P7` product · `P8` long-term |
| Audit      | `required`: the task changes analyzer behaviour on the verdict, proof or finding-accounting path, and gets an independent fresh-context audit before its PR. `no`: documentation, tooling or test infrastructure only                                                                                                                         |
| Depends on | tasks that must be `MERGED` first                                                                                                                                                                                                                                                                                                               |

Legacy task-file statuses map as: `planned` → `TODO`, `in-progress` →
`IN_PROGRESS`, `done` → `MERGED` (when its PR is merged), `superseded` →
`CANCELLED`. Old task files are not rewritten.

**Two "D" series.** `D-01` … `D-17` (two digits) are OPEN-DEBTS entries.
`D-1` (one digit) is the remediation plan's lane-D disclosure task.
