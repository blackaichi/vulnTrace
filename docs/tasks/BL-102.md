Closes RWF-145's open part, a fabricated binding masked end to end (`unsupported_receiver_binding`): the resolver (`buildDeclarationIndex`, `named-bindings.ts`) records no namespace or enum declaration, so `M` in `namespace N { namespace M { … } M.run(1); }` binds to an outer `const M`. Needs a rule for TypeScript's declaration merging (a namespace merged with a function, class or enum is that value; a namespace with no values emits no binding), read by every file-scope consumer of the resolver (ambient roots, module-scope roots, the escape row); measure the precision on the corpora and the TypeScript sources in `node_modules`. Cases: `masked.nested-namespace-shadows-an-outer-const`, `masked.enum-shadows-an-outer-const` in `tests/oracle/bl099-namespace-export-member-read.cases.ts`. Also an enum member's initializer reading another member (`enum E { A = …, B = (A as any)(1) }` emits `E.A(1)`), which the resolver binds to an outer `A` (BL-099's audit, round 4; masked, `UNKNOWN` on the base)
