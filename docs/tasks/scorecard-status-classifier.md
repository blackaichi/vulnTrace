## Project context

`docs/SCORECARD.md` is generated by `scripts/generate-scorecard.mjs` from
its sources, including the status table of `tests/validation/FINDINGS.md`,
which `scripts/scorecard-sources.mjs` (`readFindingsRegister`) classifies.
The gate `node scripts/generate-scorecard.mjs --check` fails when the
scorecard is stale. The scorecard is what a reader trusts for "what is
open", so it must never misreport a finding's status.

Premises from the prompt, to be verified (AGENTS.md section D):

- the classifier matches prose with regexes roughly like `isOpen =
  /^Open\b/i` (defeated by `**Open**`) and `isFixed = /\bfixed\b/i`
  (satisfied by "not fixed"), and it classified RWF-047 — open — as fixed
  until RWF-047's status row was reworded to dodge it;
- `generate-scorecard.mjs` contains hardcoded prose naming or
  characterising findings by status, hand-corrected twice;
- the RWF-047 classification branch recorded the classifier defect
  somewhere ("recorded, not fixed").

Forward compatibility: the next task registers sixteen audit findings
(AUD-01 … AUD-16), most open. The classifier must accept them through the
same designated field and closed vocabulary with no further change. They
are not added here.

## Task

### Problem

A status classifier that searches prose can report an open finding as
fixed. That is the scorecard's equivalent of a false `NOT_AFFECTED`.

### Why it matters

Soundness of the project's own records: the scorecard is the reader's
authority for what is open. Not an analyzer defect class; no verdict can
move.

### What to do

0. Preconditions: fetch, `main` == `origin/main`, clean tree, base SHA
   recorded; `main` contains the RWF-047 close-out
   (`src/testing/open-soundness-defect.ts`, FINDINGS RWF-047 section with
   its admissible sets); work in an own worktree.
1. Discover, before changing anything: quote the current classifier
   verbatim; enumerate every distinct status value in every register it
   classifies (FINDINGS rows; check OPEN-DEBTS D-* too); locate every
   hardcoded status prose in `generate-scorecard.mjs`; locate the record of
   the classifier defect.
2. Tests first, failing on base: `Open`, `**Open**`, `Open — classified,
   not fixed` → open; `not fixed` anywhere → never fixed; `Fixed`,
   `**Fixed**`, `Fixed (RWF-046)` → fixed; `Fixed in part`, `partially
   fixed`, `open-in-part` → open; an out-of-vocabulary value → the
   generator fails; RWF-047's current row → open.
3. Fix: status read from one designated field in a defined position;
   explicit closed vocabulary, each value mapped to exactly one category,
   markdown emphasis and surrounding punctuation stripped before lookup;
   an unknown value fails naming row and value, never defaulted; qualified
   values mapped to the category that cannot overstate closure, each
   decision reported; hardcoded status prose derived or removed; the field
   and vocabulary documented where a contributor adding a row sees them.
4. Reclassify every row; report every row whose category moved (row,
   status text, old, new); regenerate the scorecard; report open/fixed
   counts before and after.
5. Records: close the classifier-defect record with a pointer (append);
   optionally restore a plain, still-open status for RWF-047; change no
   other row's status or meaning.

## Corrections

### 2026-09-23 — premises measured differently from the task text

- **"the classifier searches a row".** It did not: it already read the
  fifth cell of the status table (`cells[4]` after splitting on `" | "`).
  The defect was the prose regexes applied *within* that cell, plus no
  header or cell-count check and a parser that silently dropped any row
  not beginning `| RWF-`. The fix keeps the one field and replaces the
  matching with a closed vocabulary.
- **"each row whose category moves is a place the scorecard was
  misreporting".** Only one row moved: RWF-013, fixed → open in part. Its
  cell's value is the scoped `Fixed for variable bindings`, mapped by the
  step-3 rule to the category that cannot overstate closure. But its own
  section says `Status: Fixed`, and its other half (RWF-013b) is fixed. So
  this move is conservative. It is not evidence of an earlier misreport.
- **Step 5, RWF-047's wording.** The new classifier handles the natural
  wording (`**OPEN — classified, not fixed**`, pinned by a test). The cell
  was still left unchanged, because
  `src/testing/open-soundness-defect.ts` (out of bounds) independently
  requires it to match `/^Open\b/`. Recorded in FINDINGS RWF-047 § 9.
- **Hardcoded status prose in § 7 narrative.** It records what measured
  blocks did, so it is kept. Each status premise it rests on (RWF-002
  open; RWF-042 and RWF-043 fixed) is declared and checked, so generation
  fails if the register disagrees. § 8's status prose is fully derived.
